# 一次仕分け仕様(デモ2)

画面は `/triage`。サンプルは [src/triage/samples.ts](../src/triage/samples.ts)、画面と処理は [src/pages/Triage.tsx](../src/pages/Triage.tsx)、エスカレーションの Claude 呼び出しは [worker/triage.ts](../worker/triage.ts)。

## 狙い

「Jev と LLM を使い分ける」ではなく、**対応の階層を分ける**という見せ方をする。

| 層 | 担当 | 役割 |
|---|---|---|
| 層0 | コード | 計算・確定ルール(AI を呼ぶ前に済ませる) |
| 層1 | **Jev** | 全件を一次受け。部署・緊急度を判定し、**確信度**で「自動で流す / 上に上げる」を決める |
| 層2 | **Claude Opus** | 上がってきた数%だけ。最終的な振り分けと、理由の一文を書く |

確信度(`choice` の `confidence`)があるから、機械的に振り分けられる。Jev の確率が実際に役立つ場面。

## 流れ

1. 「Jev で一次受け」を押すと、サンプルの問い合わせ30件を**並列6**で Jev に投げる
2. 各件の判定と確信度が、表に順次埋まる。確信度がしきい値(初期値 0.6)以上なら「自動で振り分け」、下回れば「要エスカレーション」
3. 「迷った N 件を Claude に回す」で、その件だけ Opus に投げる。最終的な部署・緊急度と**理由の一文**が付く
4. 上の集計に、層ごとの件数・時間・料金の概算が出る

- しきい値はスライダーで変えられる(0.30〜0.90)。上げるほどエスカレーションが増える
- 料金は公表単価からの概算(Jev: 入力 $0.042/100万トークン・出力無料、Opus 5: 入力 $5・出力 $25)

## サンプル

30件。はっきりした問い合わせに加えて、**わざと迷わせる文面**を混ぜてある。

- 話題が2つ混ざる: 「ログインできないと思ったら自己解決。ついでに請求書を再発行して」
- 情報が足りない: 「よろしくお願いします。」「先日問い合わせた件、その後どうなっていますか。」
- 判断が割れる: 「届いた商品が注文したものと違います。交換か返金を」(配送? 請求?)

## 計測結果(本物の API、しきい値 0.6)

| | 件数 | 時間 | 料金 |
|---|---|---|---|
| 層1: Jev | 30件(平均 253ms) | 1.5秒 | $0.0007 |
| 層2: Opus 5(effort low) | 3件(10%) | 6.1秒 | $0.016 |
| **合計** | 30件 | **7.6秒** | **$0.016** |
| 参考: 一次受けなしで全件 Opus | 30件(平均 4.5秒) | 26.1秒 | $0.153 |

- 階層にすると、**時間は約3分の1、料金は約10分の1**
- 月1万件に換算すると、Jev だけなら約30円、全部 Opus なら約7,600円
- Opus に上がった3件のうち1件(T-116「届いた商品が注文したものと違います。交換か返金を」)は、Jev が「返金」に引っ張られて請求(確信度56%)と判定したものを、**誤配送として配送に振り直した**。確信度で上げる仕組みが効いた例

`ALL_OPUS_BASELINE`(画面の参考値)は 2026-09-23 の実測。サンプルや質問を変えたら測り直す。

## ダミーモード

- 判定: キーワードで部署を決める。**話題が2つ以上混ざる・情報が少ない文面は確信度を低く**する(0.3〜0.55)ので、エスカレーションが発生する
- エスカレーション: 文中で最後に出てきた話題を最終判断とし、理由をひな形で作る
- トークン数は実測に近い値を入れてあるので、料金の概算もそれらしく出る
