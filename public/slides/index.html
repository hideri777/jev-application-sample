WHAT IT IS

Jev は「System One Model」という新しい種類

TypeSafe AI が 2026-09-15 に公開。LLM とは別のクラスの AI として打ち出している

System 1(速い思考)

直感的・一瞬。
「信号が赤 → 止まる」

→ Jev が担当するのはこちら

System 2(遅い思考)

じっくり考える。
「旅行の予算と日程を組む」

→ 今の LLM(Claude など)が得意なのはこちら

名前の由来は、ダニエル・カーネマン『ファスト&スロー』の2つの思考モード

まず「System One Model という新しいクラスを名乗っている」と伝える。そのうえで、その System 1 / System 2 とは何か、という順で話す。 今の LLM は文章を1文字ずつ書きながら考えるのでどうしても遅い。Jev は速い思考のほうだけを担当する。

WHAT IS JEV

Jev = 「判断だけ」を返す AI

応答時間

70〜500ms

公式は LLM の 40〜200倍速いと主張

料金(100万トークンあたり)

入力 出力
Jev $0.042 無料
Claude Haiku 4.5 $1.00 (24倍) $5.00
Claude Opus 5 $5.00 (119倍) $25.00
  • 文章を生成しない。決められた選択肢から、確率付きで選ぶだけ
  • 選択肢の外の答えは出ない → 形の崩れた出力や「作り話」が起きない
  • まだアーリーアクセス(待機リスト制)
文章を書かないので、1回の計算でまとめて答えを出せる。だから速い。 料金は、入力が Haiku の約24分の1、Opus の約119分の1。そのうえ出力は無料(公式いわく「安すぎて課金しない」)。 「ハルシネーションが起きない」は、あくまで選択肢の外に出ないという意味。選択肢の中で間違えることはある(後で話す)。

API

状態と質問を渡すと、確率付きの答えが返る

// POST /v1/systemone
{
  "model": "jev-latest",
  "state": {
    "勇者": { "HP": "18/100" },
    "敵": { "予兆": "大きく息を吸い込んだ！" }
  },
  "questions": {
    "action": {
      "type": "choice",
      "instructions": "次にとる最善の行動は？",
      "criteria": {
        "attack": "たたかう",
        "heal": "ベホイミで回復",
        "defend": "ぼうぎょ"
      }
    }
  }
}
// 返ってくるもの
{
  "answers": {
    "action": {
      "choice": "heal",
      "confidence": 0.62,
      "probabilities": {
        "heal": 0.62,
        "defend": 0.30,
        "attack": 0.08
      }
    }
  }
}
質問の種類は3つ
choice選択肢から選ぶ(最大255個)
score段階で評価(2〜10段階)
noulYes / No の確率
state は文字列でも JSON でもいい。質問は複数並べても遅延はほぼ変わらない。 答えは「どれを選んだか」だけでなく、各選択肢の確率が返ってくるのが特徴。

質問の型 1/3 — CHOICE

choice: 選択肢から1つ選ぶ

// 問い合わせを、どの部署に回すか
{
  "type": "choice",
  "instructions": "担当すべき部署は？",
  "criteria": {
    "billing":   "請求・支払い・返金",
    "technical": "不具合・エラー",
    "account":   "ログイン・アカウント",
    "shipping":  "配送・届かない"
  }
}
// 返り値
{
  "choice": "billing",
  "confidence": 0.56,
  "probabilities": {
    "billing": 0.56, "shipping": 0.31,
    "technical": 0.08, "account": 0.05
  }
}
  • 選択肢は最大255個
  • 振り分け・行動選択・次に押すボタン
  • 確信度で「迷ったか」が分かる
今日のデモで一番使うのがこれ。バトルの行動選択も、問い合わせの部署振り分けも choice。 確率が全部返ってくるので、1位と2位が僅差なら「迷っている」と分かる。デモ2ではこれを使ってエスカレーションを決めている。

質問の型 2/3 — SCORE

score: 段階で評価する

// 問い合わせの緊急度
{
  "type": "score",
  "instructions": "緊急度は？",
  "criteria": [
    "急ぎではない",
    "通常",
    "早めの対応が必要",
    "今すぐ対応が必要"
  ]
}
// 返り値
{
  "score": 2.31,  // 段階の「間」も返る
  "confidence": 0.72,
  "probabilities": {
    "2": 0.61, "3": 0.25,
    "1": 0.12, "0": 0.02
  }
}
  • 2〜10段階まで
  • 優先度・リスク・品質の採点
  • 整数ではなく連続値で返るので、しきい値を細かく決められる
段階の間の値が返るのがポイント。「2.31 なので、2 寄りだが 3 に近い」といった判断ができる。 アプリの模擬面接デモ(/interview)では、回答の論理性をこの型で採点している。

質問の型 3/3 — NOUL

noul: Yes / No を確率で返す

// 返金を求めているか
{
  "type": "noul",
  "instructions":
    "返金や返品を求めているか？"
}

// criteria で Yes / No の意味を
// 補足することもできる
// 返り値
{
  "noul": 0.93   // Yes の確率
}
  • フラグ判定(返金依頼か・怒っているか・要対応か)
  • 0/1 ではなく確率なので、しきい値を場面で変えられる
  • いくつ並べても遅延はほぼ増えない

※ 3つの型は1回のリクエストにまとめて入れられる

noul は聞き慣れない名前だが、中身は「Yes の確率」。0.5 で切るか 0.8 で切るかは使う側が決める。 デモ2では、1回のリクエストに choice と score を一緒に入れている。

HOW THE DEMO WORKS

同じ質問を、Jev と Claude に投げる

公平にするための工夫

  • 質問は Jev の形式で1回だけ書く
  • Claude には同じ選択肢しか答えられないように、構造化出力(JSON Schema)で縛る
  • バトルは同じ乱数の種で、同じドラゴンと戦う

並べる3つ

  • Jev — 速い判断
  • Claude Haiku 4.5 — Claude で一番速くて安い
  • Claude Opus 5 — よく考える(effort で考える量を調整)
Claude も「文章で答えて」ではなく、選択肢の enum に縛った JSON で答えさせている。 なので答えの形の差ではなく、純粋に速さと判断の中身を比べている。

バトルの判断1回あたりの平均(実測)

Jev
約 0.3秒 Haiku 4.5

約 2.4秒 Opus(medium)

DEMO 1

ドラゴンが あらわれた！

Jev・Haiku・Opus が、同じドラゴンと同時に戦う

ここからデモ。勇者の行動(たたかう・メラミ・ベホイミ・やくそう・ぼうぎょ)を毎回 AI に決めさせる。

DEMO 1 — RULES

難易度で「速さが効く」「考える力が効く」を分ける

かんたん × リアルタイム

  • 敵は 1秒ごとに勝手に攻撃してくる
  • 次の行動を予告してくれる
  • 「次の攻撃で倒れるか」も計算して渡す

→ 素早く反応できれば勝てる

むずかしい × ターン制

  • 交互に行動(待ってくれる)
  • 予告なし。敵は決まった周期で動くが、中身は履歴から読むしかない
  • 渡すのは生の数値だけ

→ 先を読んで計画しないと勝てない

ゲームのバランスは、ルールで動く自動対戦を数千回まわして決めた。 むずかしいは「周期を読める方針」なら勝率約6割、「読まない方針」だと約1割、になるよう調整してある。

DEMO 1 — かんたん × リアルタイム

敵は待ってくれない

  • 敵は 1秒ごと に攻撃してくる
  • 次の行動は予告あり・「倒れるか」も計算して渡す
  • 3つの AI が、同じドラゴンと同時に戦う
▶ 実際に見てください
結果はスライドに書かず、その場で見せる。開始1.5秒で Jev は4回、Opus は1回くらいの差が出る。 決着後に「Jev 2.5秒で勝ち、Haiku も勝ち、Opus は2回しか動けず敗北」と口頭で拾う。 そのあと Claude のログを指して、「力をためている間に防御して、防御が切れてから痛恨の一撃を受けている。 考えている間に状況が変わるので、判断が1つ前の状況に対する正解になってしまう」と話す。

DEMO 1 — むずかしい × ターン制

今度は、待ってくれる

  • 交互に行動。考える時間はいくらでもある
  • ただし予告なし・ヒントなし。敵の周期は履歴から読むしかない
  • 同じ3つの AI で、もう一度戦わせます
▶ むずかしいで戦わせる
ここも結果はスライドに書かない。ライブでは Jev と Haiku だけ先に動かし(20〜30秒)、Opus は時間がかかるので 次のスライドを話しながら裏で回すか、4戦の結果を口頭で伝える。 口頭で言う数字: 4戦ずつで Jev 0勝4敗(敵 HP ほぼ減らず)、Haiku 0勝4敗(あと1〜2手)、Opus 4勝0敗。

INSIGHT

負け方に、それぞれの性格が出る

Jev

最初に1回攻撃した後、ずっと防御。4戦とも行動の並びがまったく同じ

ヒントが無いと、安全そうな選択に逃げる

Haiku

攻めることはできるが、防御のタイミングがずれる。回復も少なめ

先を読めずに、あと一歩届かない

Opus

序盤はメラミで攻め、HP が減れば回復、MP が切れたら通常攻撃

周期を完全に読めたわけではない(痛恨の前の防御は 3/8)。資源の配分で勝った

「Opus が周期を読んだから勝った」わけではないのがポイント。計画的に立ち回れる、というのが正確。 Jev は計算済みのヒントが無いと崩れる。これは最初の版でも同じ現象が出ていた。

TRADE-OFF

速さと、考える力のトレードオフ

かんたん(時間の制約がきつい)

Jev > Haiku > Opus

速いほど勝つ

むずかしい(よく考える必要がある)

Opus > Haiku > Jev

考えるほど勝つ

ここからデモ2。実務にありそうな話として、問い合わせの一次仕分けを見せる。 ポイントは「Jev か LLM かを選ぶ」のではなく「一次受けは Jev、上がってきたものだけ LLM」という階層の話。

DEMO 2 — 一次受け → エスカレーション

Jev が全件を受け、迷った分だけ上に上げる

層1: Jev(一次受け)

  • 30件すべてを判定
  • 部署・緊急度に加えて確信度が返る
  • 確信度が高ければ、そのまま自動で振り分け

層2: Claude Opus(エスカレーション)

  • 確信度が低い件だけを受け取る
  • 最終的な振り分けと理由の一文を書く
  • 時間もお金もかけてよい(数が少ないので)

しきい値(例: 確信度 0.6)を動かすと、「自動で流す割合」と「人・LLM に回す割合」を調整できる

▶ 一次仕分けを開く
確信度は Jev が返す確率分布から出てくる値。これがあるから「迷ったかどうか」で機械的に振り分けられる。 ライブではしきい値のスライダーを動かして、エスカレーション件数が増減するのを見せると分かりやすい。

DEMO 2 — 結果(問い合わせ30件・実測)

7.6秒・2円弱で30件をさばく

件数 時間 料金
層1: Jev 30件(平均 253ms) 1.5秒 $0.0007
層2: Opus 3件(10%) 6.1秒 $0.016
参考: 全部 Opus 30件 26.1秒 $0.153

階層にすると 時間は約3分の1、料金は約10分の1。しかも Opus は、Jev が迷った1件を 「請求 → 配送」に直した(誤配送なので、まず配送部門で事実確認が必要)

料金の桁が小さく見えるが、これは30件の話。月1万件なら Jev だけで約30円、全部 Opus なら約7,600円。 直した1件は T-116「届いた商品が注文したものと違います。交換か返金を」。Jev は「返金」に引っ張られて請求と判定(確信度56%)。 Opus は誤配送と読んで配送に振り直した。確信度が低い件を上げる仕組みが効いた例。

WHERE IT FITS

対応の階層

層1(Jev)に置くもの

  • 大量の振り分け・分類(問い合わせ、ログ、チケット)
  • 画面操作やゲームなど、状況が動く中での判断
  • 全件に必ず通す「一次受け」

層2(LLM)に上げるもの

  • 文章を書く・要約する(Jev はそもそもできない)
  • 何段階も推論が要る判断、例外的な事案
  • Jev が迷った件(確信度が低いもの)

層0: コード(計算・確定ルール) → 層1: Jev(全件を一次受け・確信度で振り分け) → 層2: LLM(上がってきた数%だけ)

この形は公式ガイドでも「カスケード」としてすすめられている。デモ2がまさにこの形。 アプリには模擬面接のデモ(/interview)もあり、質問は Haiku、採点は Jev、講評は Opus と同じ考え方で分けている。聞かれたら見せる。

CAVEATS

注意点と、批判的な意見

  • 精度は大型 LLM と同じくらい(独自ベンチで約68%)。選択肢の中で間違えることはある
  • 普通の LLM でも、答えを1トークンに絞れば近い速さが出せるのでは? という指摘もある
  • ユーザーの入力を state に入れると、答えを誘導されうる(対策が必要)
  • jev-latest は予告なく更新される。しきい値を調整するならバージョンを固定する
  • まだアーリーアクセス。待機リスト制

出典: TypeSafe AI 公式ブログ / API リファレンス、Sean Goedecke「Jev means structured output is interesting again」ほか(docs/jev.md)

持ち上げすぎないように、弱点と批判も紹介しておく。
