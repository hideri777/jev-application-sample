カーネマンの System 1 / System 2。今の LLM は文章を1文字ずつ書きながら考えるので、どうしても遅い。 Jev は「速い思考」のほうを担当する AI、という位置づけ。

WHAT IS JEV

Jev = 「判断だけ」を返す AI

応答時間

70〜500ms

公式は LLM の 40〜200倍速いと主張

料金(入力)

$0.042/100万トークン

出力は無料(too cheap to meter)

  • 文章を生成しない。決められた選択肢から、確率付きで選ぶだけ
  • 選択肢の外の答えは出ない → 形の崩れた出力や「作り話」が起きない
  • TypeSafe AI が 2026-09-15 にアーリーアクセス開始(待機リスト制)
文章を書かないので、1回の計算でまとめて答えを出せる。だから速い。 「ハルシネーションが起きない」は、あくまで選択肢の外に出ないという意味。選択肢の中で間違えることはある(後で話す)。

API

状態と質問を渡すと、確率付きの答えが返る

// POST /v1/systemone
{
  "model": "jev-latest",
  "state": {
    "勇者": { "HP": "18/100" },
    "敵": { "予兆": "大きく息を吸い込んだ！" }
  },
  "questions": {
    "action": {
      "type": "choice",
      "instructions": "次にとる最善の行動は？",
      "criteria": {
        "attack": "たたかう",
        "heal": "ベホイミで回復",
        "defend": "ぼうぎょ"
      }
    }
  }
}
// 返ってくるもの
{
  "answers": {
    "action": {
      "choice": "heal",
      "confidence": 0.62,
      "probabilities": {
        "heal": 0.62,
        "defend": 0.30,
        "attack": 0.08
      }
    }
  }
}
質問の種類は3つ
choice選択肢から選ぶ(最大255個)
score段階で評価(2〜10段階)
noulYes / No の確率
state は文字列でも JSON でもいい。質問は複数並べても遅延はほぼ変わらない。 答えは「どれを選んだか」だけでなく、各選択肢の確率が返ってくるのが特徴。

HOW THE DEMO WORKS

同じ質問を、Jev と Claude に投げる

公平にするための工夫

  • 質問は Jev の形式で1回だけ書く
  • Claude には同じ選択肢しか答えられないように、構造化出力(JSON Schema)で縛る
  • バトルは同じ乱数の種で、同じドラゴンと戦う

並べる3つ

  • Jev — 速い判断
  • Claude Haiku 4.5 — Claude で一番速くて安い
  • Claude Opus 5 — よく考える(effort で考える量を調整)
Claude も「文章で答えて」ではなく、選択肢の enum に縛った JSON で答えさせている。 なので答えの形の差ではなく、純粋に速さと判断の中身を比べている。

LATENCY

まず、どれくらい速いか

バトルの判断1回あたりの平均(実測)

Jev
約 0.3秒 Haiku 4.5
約 0.9秒 Opus(low)
約 2.4秒 Opus(medium)
約 5.7秒

一番速い Claude(Haiku)と比べても約3倍、よく考える Opus とは約18倍の差

数字は docs/presentation.md と battle.md の実測値。Jev 約 293〜310ms、Haiku 約 0.9〜1.0秒、Opus low 約 2.4秒、Opus medium 約 5.7秒。 ネットワークの時間も含む。初回だけは Jev でも 600ms くらいかかる。

DEMO 1

ドラゴンが あらわれた！

Jev・Haiku・Opus が、同じドラゴンと同時に戦う

ここからデモ。勇者の行動(たたかう・メラミ・ベホイミ・やくそう・ぼうぎょ)を毎回 AI に決めさせる。

DEMO 1 — RULES

難易度で「速さが効く」「考える力が効く」を分ける

かんたん × リアルタイム

  • 敵は 1秒ごとに勝手に攻撃してくる
  • 次の行動を予告してくれる
  • 「次の攻撃で倒れるか」も計算して渡す

→ 素早く反応できれば勝てる

むずかしい × ターン制

  • 交互に行動(待ってくれる)
  • 予告なし。敵は決まった周期で動くが、中身は履歴から読むしかない
  • 渡すのは生の数値だけ

→ 先を読んで計画しないと勝てない

ゲームのバランスは、ルールで動く自動対戦を数千回まわして決めた。 むずかしいは「周期を読める方針」なら勝率約6割、「読まない方針」だと約1割、になるよう調整してある。

DEMO 1 — かんたん × リアルタイム

速い Jev が勝ち、賢い Opus は間に合わない

結果 かかった時間 行動回数 平均判断時間
Jev 勝利 2.5秒 8回 293ms
Haiku 4.5 勝利 6.6秒 7回 927ms
Opus 5(low) 敗北 8.0秒 2回 2,357ms

Opus は考えている間に殴られ続け、2回しか動けずに倒れた

▶ バトルを開く
ライブで「かんたん」のまま「たたかう！」を押す。開始1.5秒で Jev は4回、Claude は1回、くらいの差が目に見える。 Opus は賢くても、敵を待たせられないと勝てない。

INSIGHT

遅いと、判断が「古く」なる

ドラゴンは 力をためている…
勇者は 身を守っている　← ためている間に防御してしまう
ドラゴンは 痛恨の一撃！ 勇者は 46 のダメージ　← 防御が切れた後に大技
  • 考えている間に状況が変わり、「1つ前の状況」に対する正しい判断をしてしまう
  • 速さは快適さの問題ではなく、判断の正しさそのものに効く
リアルタイムの Claude のログから。判断そのものは間違っていないが、判断が返ってきたときにはもう状況が変わっている。 ゲームだけでなく、監視・アラート・UI の反応など、「状況が動くもの」全般に言える。

DEMO 1 — むずかしい × ターン制(4戦ずつ)

考える必要があると、立場が逆転する

勝敗 負けたときの敵の残りHP(最大210) 平均判断時間
Jev 0勝4敗 約190(ほぼ削れない) 約 310ms

Opus 5(medium) 4勝0敗 — 約 5.7秒
▶ 「むずかしい」で戦わせる
Opus は1戦1〜2分かかるので、先に Jev と Haiku だけ動かして話を進め、Opus は後から動かす(前回の結果が画面に残る)。 Opus の費用は1戦あたり約 $0.15。

INSIGHT

負け方に、それぞれの性格が出る

Jev

最初に1回攻撃した後、ずっと防御。4戦とも行動の並びがまったく同じ

ヒントが無いと、安全そうな選択に逃げる

Haiku

攻めることはできるが、防御のタイミングがずれる。回復も少なめ

先を読めずに、あと一歩届かない

Opus

序盤はメラミで攻め、HP が減れば回復、MP が切れたら通常攻撃

周期を完全に読めたわけではない(痛恨の前の防御は 3/8)。資源の配分で勝った

「Opus が周期を読んだから勝った」わけではないのがポイント。計画的に立ち回れる、というのが正確。 Jev は計算済みのヒントが無いと崩れる。これは最初の版でも同じ現象が出ていた。

DEMO 2 — LIVE FORM

打っている最中に、フォームが変わる

1回のリクエストで4つ判定

  • 担当部署(choice)
  • 緊急度(score)
  • 返金を求めているか(noul)
  • 怒っているか(noul)

返金なら「注文番号」欄、急ぎなら「優先窓口」の案内がその場で出る

「途中で話が変わる」文を自動入力

約1.8秒時点 入力完了後
Jev 7文字遅れ 判定11回
Haiku 26文字遅れ 判定4回

どちらも最後は「請求・支払い」に切り替わった

▶ フォームを開く
「途中で話が変わる」は「ログインできない…と思ったら解決、ついでに請求書を再発行して」という文。 Jev だけが入力にほぼ追いついて、判定が切り替わる様子が見える。「フォームを動かす判定」を Claude に切り替えると、欄が出るのが遅れる。

LESSONS

作ってみて分かったこと

計算はコードで済ませる

Jev は計算・数を数えるのが苦手

「次の攻撃で倒れるか」をコードで計算して渡したら、防御ばかりの Jev が戦えるようになった

指示の一言が強く効く

「基本は攻撃する」と書いたら、今度は Claude が回復を一度も使わず全敗

中立に書き直して、Jev 4/6勝・Haiku 3/6勝に落ち着いた

確信度が迷いを教えてくれる

説明が足りないと、確率が横並び(確信度 6%)になる

書き方を見直すサインとして使える

Jev は「書いた質問を、書いたとおりに」読む。否定語や範囲の言葉にも注意。 ここは Jev に限らず、LLM に判断させるとき全般に効く話。

WHERE IT FITS

向いている使い方

向いている

  • 大量の振り分け・分類(問い合わせ、ログ、チケット)
  • 画面操作やゲームなど、状況が動く中での判断
  • 入力中・操作中のリアルタイムな反応

向いていない

  • 文章を書く・要約する(そもそもできない)
  • 計算や、何段階も推論が要る判断
  • 画像・音声の入力(今はテキストだけ)

おすすめの構成は「カスケード」: Jev で安く振り分け → 単純な処理はコード → 難しいものだけ大型 LLM へ

カスケードは公式ガイドでもおすすめされている形。模擬面接の appendix を作るなら、まさにこの形(Claude が質問、Jev が即採点)。

CAVEATS

注意点と、批判的な意見

  • 精度は大型 LLM と同じくらい(独自ベンチで約68%)。選択肢の中で間違えることはある
  • 普通の LLM でも、答えを1トークンに絞れば近い速さが出せるのでは? という指摘もある
  • ユーザーの入力を state に入れると、答えを誘導されうる(対策が必要)
  • jev-latest は予告なく更新される。しきい値を調整するならバージョンを固定する
  • まだアーリーアクセス。待機リスト制

出典: TypeSafe AI 公式ブログ / API リファレンス、Sean Goedecke「Jev means structured output is interesting again」ほか(docs/jev.md)

持ち上げすぎないように、弱点と批判も紹介しておく。

SUMMARY

まとめ

  • Jev は、文章を書かない代わりに 0.3秒で判断する AI
  • 状況が動く場面では、速さが判断の正しさを決める
  • よく考える場面では、Opus のような LLM が強い
  • 両方を場面で使い分けるのが実用的
